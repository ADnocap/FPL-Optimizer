# 2026-27 GW1-5 review: performance, what was wrong, what changed

Entry 8737706. Written 2026-09-25 (international break; GW6 deadline 2026-10-10 10:00Z).
Method: 7 independent investigators (prediction quality, train/serve skew, synthetic-row
parity, decision audit, GW5 deep dive, live-code review, historical context), every
material claim re-derived by an adversarial verifier and, for high-severity ones, a
second impact verifier; then 7 model-experiment families and a rules/chips/transfers
audit, each verified the same way. Claims that did not survive verification are not
repeated here.

## 1. Bottom line

- **296 points vs 299 for the average manager (-3, rank 4.84M) is noise.** The SD of a
  5-GW total vs the field is ~25-32 (z ≈ -0.1); GW5's -12 is ~-1 SD. About 55% of the
  field has played a chip worth +3-4 so far; we hold all eight.
- **The points came from the human layer, not the model.** Following the model with
  uncapped transfers would have scored **239 (-57)**: -24 in hits on over-predicted
  buys, ~-21 from model captains, ~-10 from the GW2 João Pedro → Gyökeres swap. Every
  override beat the model (+48 one GW at a time, +57 over the path).
- **Root cause: the model's #1 feature was a leak.** vaastav's `xP` is FPL's `ep_this`
  read *after* the gameweek, when FPL has already recomputed it with that gameweek's
  own points in form. The model learned to lean on it; live it gets the honest
  pre-deadline value and mis-ranks (inflated top end: predictions ≥6 averaged 7.11 and
  returned 2.75). `EP_FORMULA.md`'s "not a leak" was tested mid-GW, before the recompute.
- **The advertised numbers were leak artifacts.** Holdout per-GW Pearson 0.632 = 0.87 on
  the 11 GWs with scraped xP + 0.54 on the 27 without. The README's 2,918 (2024-25)
  becomes ~1,850-2,020 when the model is served as it runs live (field average 2,008).
- **Everything else in the pipeline was largely sound** (engine reproduces 296 exactly;
  MILPs match brute force; entry-state rebuild correct; synthetic deadline rows match the
  real rows on 120/122 features) — but several secondary gaps compounded the leak (§4).
- **Fixed and rebuilt (§5):** leak-free features, a stronger model (live per-GW Spearman
  0.654 → 0.707 on GW1-5; holdouts 0.742 / 0.732), servable feature set, calibrated
  availability, a multi-GW planner (the new weekly default: it beat the
  single-GW optimizer in every leak-free season replay), a 207-test rules suite,
  data-health checks and decision logs.

## 4. Soundness audit — defects found (all fixed)

| # | Defect | Effect | Fix |
|---|---|---|---|
| 1 | **xP same-GW leak** (critical) | #1 feature; top end inflated; hit-chasing | `fpl_xp_lag` (previous GW's xP; live = the deadline snapshot's `ep_this`, the identical quantity); missing-scrape GWs NaN |
| 2 | **understat same-day leak** | a match on the GW's first-kickoff day entered that GW's features (14.5% of rows) | compare calendar days |
| 3 | **22+ features empty at every live deadline** (understat never collected; h2h odds file missing; FBref dead) | serving them empty cut captain-pick points 8.1 → 4.9 on holdout | train only on servable features; odds now built from football-data (+ Odds API fallback); data-health check each run |
| 4 | Team strengths published as 0 by the 2026-27 API | opponent-strength features 0 in GW1-4 | fixed before GW5 (fa8374c); verified correct |
| 5 | Past rows stamped with the player's *current* club | 566 fake double-GW rows; opponent features inflated | club from the fixture side |
| 6 | Element-summary refresh deleted everything, ignored failures | 3 missing files moved Haaland 5.2 → 10.4 | atomic staging refresh; abort on failure |
| 7 | `--skip-refresh` had no staleness guard | stale form (Stach 8.35 → 3.74) | refuses summaries older than the last GW's results |
| 8 | Flags: 75% applied as 0.75× (and twice via xP) | 75%-flagged players played 25% of the time | one calibrated multiplier (75% → 0.40×, 50% → 0.25×, 25% → 0.10×) |
| 9 | Backtests gave 2 FTs in GW2; FH didn't restore the bank; WC/FH allowed in GW1; blank-GW squad players got club 0 | inflated backtests / engine errors | engine + backtest fixes (rules suite) |
| 10 | `--apply` planned on the public reconstruction; could cancel a chip already active on the site | wrong FT/bank at submission; lost chip | plans on authenticated my-team state; refuses a mismatched active chip |
| 11 | No decision logs | GW5's plan was unreproducible | `data/live/{season}/decisions/gw{N}_*.json` |

Checked and sound: engine replay (reproduces 40/99/52/69/36 and bench points), transfer
and lineup MILPs vs brute force, FT/bank/selling-price reconstruction (2 FTs, £0.2m into
GW6), all chip windows and payloads, synthetic deadline rows, ID mapping (667/667).

## 5. What changed

**Predictor (model of record from 2026-09-25, `scripts/train_predictor.py` RECIPE):**
- Leak-free `fpl_xp_lag`; understat day filter; features that can't be served
  reliably at a deadline excluded (understat rolling, FBref-only priors, 2016-19-only
  stats, h2h odds, and the team strengths the 2026-27 API only publishes as a 1-5
  rating) — 121 features. Deadline ownership reconstructed instead of rounded for
  low-owned players.
- Minutes model: P(plays), P(60+) from minutes-history features (nested by season for
  training rows); prediction = ½ factorized (P60·E[pts|60+] + P(1-59)·E[pts|1-59]) +
  ½ stacked points model — the largest single gain (+0.015 Spearman, 38/38 GWs on both
  holdouts).
- Huber loss, min_child_samples 50, monotone quadratic calibration (+0.012, overlapping).
- Trains on complete seasons + the current season's completed GWs (early stopping on the
  last complete season).

| Per-GW Spearman | Leaky model served live | Leak-fixed baseline | **v5** |
|---|---|---|---|
| Holdout 2025-26 | 0.692 | 0.726 | **0.742** |
| Holdout 2024-25 | 0.670 | 0.719 | **0.732** |
| Live 2026-27 GW1-5 | 0.654 | 0.685 | **0.711** |

Against a baseline with the understat leak also removed, v5 is better or equal on every
honest metric (top-10 5.07 vs 4.99, captain 6.55 vs 6.47, MAE 0.945 vs 0.989 on
2025-26). Hauler under-prediction remains (typical for every public model).

Tried and rejected (evidence in the experiment logs): prior-season FPL features /
cross-season form / shrinkage (no early-season gain), captain upside heads and
bookmaker-props captaincy (argmax of the prediction stays best), recency weighting,
dropping xP entirely (-0.004 on 2024-25), DNP-risk bench weights in the single-GW MILP.

**Optimizer and rules** — leak-free season replays with the v5 model (evaluation
model trained only on earlier seasons; every GW through the rules engine):

| Net points | 2023-24 | 2024-25 | 2025-26 |
|---|---|---|---|
| 3-GW planner (hit margin 4) — **new weekly default** | **2,293** | **2,467** | **2,129** |
| Single-GW, max 1 transfer | 2,208 | 2,342 | 2,048 |
| Single-GW (4-pt hit rule) | 2,144 | 2,333 | 2,069 |

- The planner won every season (+60 to +149 vs single-GW). With the better
  predictor its later-GW forecasts beat reusing this week's (+0.02-0.04 Spearman),
  which the older model's did not. A 6-GW horizon and a single-GW hit margin of 2
  both lost.
- Chip schedules in replays (TC7/BB12/FH18; a GW11 Wildcard) moved totals by -145
  to +84 and average ~0 — within single-replay noise; an earlier run with a slightly
  different recipe even had the opposite Wildcard sign. Chip timing stays the
  approved human plan; `scripts/chip_eval.py` gives calibrated values at each
  decision point, and `--wc-move-cost` can make a Wildcard change only what clearly
  pays.
- Rules regression suite (207 tests) against the API's own 2026-27 config.
- An adversarial five-lens review of the whole change set (live path, leakage,
  rules/chips, data collectors, train/serve parity) found no leak; its confirmed
  findings were fixed before going live (e.g. a leaky-model guard, cp1252 crash on
  player names, atomic summary refresh on Windows, ownership reconstruction).

## 6. Expectations and process from here

- An honest predict-and-optimize system is worth roughly **+2 to +5 pts/GW over the
  average** (top 10-50% finishes), with ±100-250 pts of path noise per season — not the
  top-1% the leaky numbers implied. Judge by diagnostics (per-GW correlation vs FPL EP,
  calibration of predictions ≥5, realised vs predicted transfer gains), not rank, until
  half the season is played: ~33 GWs are needed to show a +4.5/GW edge at 2 SE.
- Keep the human veto, formalised: hits need > 4 + margin; captain is the user's call
  (the output shows model vs EP vs bookmakers); never a flagged captain.
- Run close to the deadline; read the data-health block; keep the decision logs.
- Retrain at ~GW10, GW19, GW30 (`/retrain`); the in-season gain grows with the rows.
